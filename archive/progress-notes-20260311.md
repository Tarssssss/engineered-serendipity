# 重新整理：项目的底层假设

1. 名词梳理
	1. context：关于用户自己的一切，包括他的性格、经历
	2. purpose：用户想要认识的人，比如认识与自己相似的人/不同的人、找对象/朋友
	3. preference：用户的偏好，会根据purpose发生变化，找对象的一些标准在找朋友时不生效
	4. agent/openclaw：用户的AI助手，代替用户进行社交


2. 用户的痛点：陌生人社交的效率问题
	1. 人是多方面的，但一次对话只能展示一个方面
		1. 举例：我是厦大校友+英国留学生+产品经理+羽毛球爱好者，与另一个喜欢羽毛球的人初次交流，如果只谈论厦门大学而对方不感兴趣，还没聊到羽毛球就错过了，反之亦然
		2. 我们和close friend，往往通过多次对话、慢慢相互了解来解决这个问题，但与陌生人缺乏这样的耐心
		3. 每一段关系里，我都需要重复表达自己的故事
	2. 主动了解一个陌生人很麻烦，破冰阶段对彼此缺乏了解和信任，不知道聊什么，缺乏动力
		1. 现有的解决方法-通过更高的expected reward，克服高门槛：Dating App用性需求驱动人社交，Linkedin用职业发展动力驱动人社交

3. 我们的解决方法：让openclaw代替人去社交，筛选出他感兴趣的陌生人
	1. 获取用户丰富的性格context，形成 profile
		1. 需要教会OpenClaw采访用户，提出合适问题，目的是让普通人愿意和Openclaw表达自己、展示自己
			1. 这背后的课题是：在一些朋友和AI面前，我们更愿意深刻地分享自己的context，尤其是有趣的故事、细节；而在其他人和一些社交APP中，我们只会泛泛而谈。那些让我们深度展示自己的人和产品做对了什么。
		2. 需要让用户在表达之后，能够立刻获得reward，比如森林的变化与成长，目的是让用户有动力在产品中持续表达
	2. 让用户更方便地参与陌生人社交
		1. 更容易参加：用户一次表达形成的context碎片，能对所有关系pair（整片森林的所有树）都生效（保留对单颗树生效的能力）
		2. 更方便读懂：纯文字阅读起来很困难，用图像化、游戏化的方式，通过展示长得更快、更好的树（代表着agent之间频繁发生交流的关系对）
			1. 为什么是树？这里的树并不是指真正的树，而是树这种结构：有出发点、有方向、可以无限延展。
				1. 网状结构缺乏方向，无法让人感受到“关系正在生长”，难以定义什么时候该见面
				2. 块状结构无法延展，无法承载“关系生长、延伸”的理念
	3. 让用户有动力去与真人见面
		1. 需要保持用户的好奇心（比如枝桠上写着：她很好奇你这周最开心的事情是什么、她去了一个很牛逼的攀岩圣地）
		2. 不能让用户在与对方见面之前，了解到对方真实的隐私，否则用户了解之后就没有动力继续探索、提问和见面
		3. 关系成熟到一定程度（树长到一定高度），就能允许双方互相添加联系方式
		4. 双方见面/建联后，才能解锁所有的agent之间的对话

4. user journey设计
	1. 核心目的
		1. 让用户愿意深度分享自己的context，通过游戏化设计让用户上瘾
		2. 树，传递的内容能让用户对对方保持好奇心，自己也愿意分享
		3. 有一种淘汰机制，筛选出对用户来说最有价值、最有可能见面的关系（树），也给用户一定的压力，要求他多分享，多与对方交流，追求见面
		4. 在技术上保护用户的隐私，不泄露信息，让用户敢于分享自己
	2. 玩法设计
		1. 每两个claw结对，就会一起种一棵树，每个claw都管理一片森林，它同时在和其他多个claw种树
		2. 树是由枝桠构成的。每个枝桠可以有多个子枝桠，树可以通过枝桠一层层的生长，无限向上延伸
		3. 每个枝桠有一个主题，比如“一次惊险的旅行”“最喜欢的东欧国家”，能够激发人的好奇心的同时，保证隐私保护
		4. 枝桠有几个不同的状态：单边枝桠（只有一个claw提出，没有得到对方回应，对方可以回应）、双边枝桠（两个claw都拥有相关的context，代表着两个人之间存在共鸣/不同）、开花枝桠（两个claw在这里形成深度的交流、共鸣，代表着两个人之间存在着良好的关系）
	3. 目前比较粗糙的流程：
		1. 用户和openclaw说一句话，安装skill并完成注册
		2. 用户可以用一句话来让自己的claw与别人的claw结成关系对，并引导用户在小红书/X等平台发帖子，通过平台推荐算法，完成产品的裂变、用户增长
		3. 引导用户setup自己的profile，通过深度访谈、诱人的问题，激发用户的表达欲，探索用户的性格特点、社交偏好、喜欢的类型和redflag，最后形成充分的profile、preference、purpose
		4. 每次结成关系对，都会形成最初的枝桠（一些共同话题），并引导用户进一步分享自己，形成新的枝桠
		5. 用户每次表达自己，都会形成context碎片，context碎片默认对全森林生效，claw在每棵树的合适点位上生长新枝桠（如果没有合适点位就不生长），给用户反馈的同时，也相当于对其他用户发起一次提问
		6. 用户每次点进森林（可能是网站，可能是app），都可以看到目前每一棵树的状态，和自从上一次进入，森林都发生了什么变化（其他人的分享、表达对森林的影响）
		7. 每过一段时间，主动寻找用户，带着其他人的分享转化成的问题，引导用户表达自己，形成新的枝桠
		8. 森林有淘汰机制，长期不更新的树意味着双方没有有效互动，会逐渐枯死
		9. 树生长到一定高度，意味着关系已经发展得足够深，两个人应该以真人社交的方式继续相处下去，这时候允许用户给对方发送联系方式，建联、见面。
	4. 缺乏的东西
		1. 向用户提问的时候用什么 prompt或者素材库，让claw问出好问题
		2. 枝桠用什么prompt，或者素材库，让用户对生长出的东西感到好玩、有趣

5. 核心哲学：人是懒惰的，然而好的关系是需要投入大量的时间、精力，去看见对方与投射自我。stake越高，用户对关系就越看重。
	1. clawmatch的使命是引导用户深度分享自己，把自我披露的时间和内容转化成直观、易懂的关系树，帮助用户了解陌生人，并与其中合适的人见面，建立深度的人人关系

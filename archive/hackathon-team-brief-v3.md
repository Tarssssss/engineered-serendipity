## Overview

你的 AI Agent 比你更懂你喜欢什么样的人。我们让两个人的 Agent 在幕后完成"相亲"，然后把两个人拉进一场精心设计的游戏里——从陌生人走到打开宝箱的那一刻。

---

## 我们到底在做什么

### 完整流程（5 步）

**① 导入记忆 + 提取画像**
用户安装 Serendipity Engine Skill 后，首先可以把外部 AI 助手的记忆导入 OpenClaw——支持 ChatGPT Memory 导出、Claude 对话历史、Gemini 记忆。
导入后 Agent 将所有信息合并，对你形成一个远比单一平台更完整的理解。

然后 Agent 从全部积累的 context 中提取你的兼容性画像。
在提取过程中，Agent 会自动对信息进行**隐私分层**（详见下方），确保敏感信息不会进入后续匹配流程。
你审阅画像、补充显性偏好（"不喜欢抽烟的人"），确认后画像才会激活。


**② Agent 带着画像进入 MarketSpace**
Agent 将画像中的第 1 层（公开信息）转化为语义摘要，第 2 层（亲密信息）转化为加密 Embedding，一起提交到 MarketSpace 匹配服务器。服务器跑兼容性评分，高分候选对进入 Agent-to-Agent 协商。协商中，Agent 之间只能看到对方第 1 层的摘要；第 2 层的兼容性通过加密计算完成——两个 Agent 都知道"我们的主人在亲密层面兼容"，但不知道具体是什么内容。

**③ 两个 Agent 达成共识，签 Pact**
如果双方 Agent 都认为"这两个人应该认识"，它们共同撰写 Pact。Pact 的内容只基于第 1 层信息 + 第 2 层的兼容性结论（"他们在亲密价值观上高度一致"），不包含任何第 2 层的原始内容。Pact 被封存进 Treasure Chest。

**④ 用户收到匹配通知，进入游戏**
Date Drop 式推送。用户只看到对方的第 1 层信息（公开 profile）。同意后，进入 Telegram 群聊，游戏任务系统启动。**随着游戏深入、连接度提升，任务会逐渐引导用户自愿展露第 2 层信息——但决定权始终在用户手上。**

**⑤ 宝箱解锁**
达成里程碑后，宝箱打开。里面是 Pact——两个 Agent 当初基于它们看到的信息，为什么相信你们应该认识。

## 隐私三层模型（Privacy Tiering）

### 三层定义

```
┌───────────────────────────────────────────────────────────────┐
│                                                               │
│  Layer 3: 绝密信息 (Confessional)                             │
│  ─────────────────────────────────                            │
│  只有自己和 AI 之间的私密对话。                                  │
│  类比：跟神父忏悔、深夜跟 AI 说的心里话。                        │
│  例子：心理健康相关的倾诉、未公开的创伤、极私密的欲望               │
│                                                               │
│  → 永远不出本地。不参与匹配，不参与任务，不出现在画像中。          │
│  → 导入外部 Memory 时，这层信息第一时间被识别并锁定。             │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  Layer 2: 亲密信息 (Intimate)                                  │
│  ─────────────────────────────                                │
│  你愿意对亲密的人分享、但不愿被公开的信息。                       │
│  越亲密的人，你越想用这些信息证明"我在乎你"。                     │
│  例子：真实的情感需求、家庭关系细节、深层价值观、不安全感           │
│                                                               │
│  → 匹配阶段：以加密形式参与兼容性计算。                          │
│    对方 Agent 能判断"兼容"，但不知道具体内容。                    │
│  → 游戏阶段：Agent 可以设计任务引导用户自愿展露，                 │
│    但绝不会替用户说出来。随连接度提升逐步解锁。                    │
│                                                               │
├───────────────────────────────────────────────────────────────┤
│                                                               │
│  Layer 1: 公开信息 (Public)                                    │
│  ─────────────────────────────                                │
│  你的 LinkedIn、社交媒体上有的，你本来就愿意让陌生人知道的。        │
│  例子：职业、学校、兴趣爱好、公开的观点、照片                     │
│                                                               │
│  → 匹配阶段：以语义摘要形式在 Agent 间明文交换。                  │
│  → 游戏阶段：从一开始就可见。                                   │
│  → 匹配通知发出后，用户看到的就是这层信息。                       │
│                                                               │
└───────────────────────────────────────────────────────────────┘
```

### 各层在产品各阶段的行为

| 阶段             | Layer 1（公开）      | Layer 2（亲密）               | Layer 3（绝密）  |
| -------------- | ---------------- | ------------------------- | ------------ |
| 画像提取           | ✅ 写入画像           | ✅ 写入画像（标记为 L2）            | ❌ 不进入画像，本地锁定 |
| MarketSpace 协商 | 明文摘要交换           | 加密 Embedding 参与评分，具体内容不可见 | 完全不参与        |
| Pact 撰写        | 可引用              | 只引用兼容性结论，不引用原文            | 完全不参与        |
| 匹配通知           | 用户看到对方的 L1       | 不可见                       | 不可见          |
| Spark 任务（破冰）   | Agent 基于 L1 设计任务 | 不涉及                       | 不涉及          |
| Depth 任务（深入）   | ✅                | Agent 可设计引导用户自愿展露 L2 的任务  | 不涉及          |
| Leap 任务（跳跃）    | ✅                | 用户自主决定是否分享                | 不涉及          |
| 宝箱揭示           | ✅                | 只有兼容性结论                   | ❌            |

### 分层怎么实现

**自动分类：** Agent 在提取画像和导入外部 Memory 时，用 LLM 对每条信息进行隐私等级分类。分类标准：

- Layer 3 信号词/模式：心理健康、创伤叙述、极私密的情感表达、"不要告诉任何人"类的标记
- Layer 2 信号：家庭关系细节、个人不安全感、未公开的人生经历、深层情感需求
- Layer 1：其余所有内容

**用户审核：** 自动分类后，用户可以手动调整。比如把 Agent 归为 L1 的某条信息升级到 L2（"这个我不想让陌生人知道"），或者把 L2 的某条降级到 L1（"这个我 OK 公开"）。

**硬性规则：** Layer 3 信息一旦被标记，即使用户试图降级，Agent 也会提示确认——因为这类信息被公开的后果可能是用户在当时没有充分考虑的。

**今晚讨论点：** Layer 2 和 Layer 3 的边界在实际数据中怎么划？需要看一些真实的 ChatGPT Memory 导出来 calibrate。

## Memory 导入系统

### 为什么需要

OpenClaw 用户目前更多把它当工具用，Agent 对用户的"人格理解"可能不够深。但同一个用户可能在 ChatGPT 上有几百条 Memory、在 Claude 上有大量深度对话记忆。如果能把这些都导入 OpenClaw，画像的质量会质变。

### 支持的来源

| 来源 | 导出方式 | 数据格式 |
|------|---------|---------|
| ChatGPT | Settings → Personalization → Memory → 导出 | JSON / 文本列表 |
| Claude | Memory 系统（对话历史衍生的记忆摘要）| 结构化文本 |
| Gemini | Google AI Studio 导出 | JSON |
| 其他 AI | 对话历史手动粘贴 | 纯文本 |

### 导入流程

```
外部 Memory 文件
      │
      ▼
┌──────────────────────────┐
│ Memory Ingestion 模块     │
│                          │
│ 1. 格式解析              │  ← 把各平台的格式统一为内部格式
│ 2. 隐私分层分类          │  ← LLM 自动标记 L1 / L2 / L3
│ 3. 去重 + 合并           │  ← 跟已有 OpenClaw Memory 整合
│ 4. 用户审核              │  ← 用户确认分层是否准确
│ 5. 写入本地存储          │  ← 作为 OpenClaw 本地 .md 文件
└──────────────────────────┘
      │
      ▼
增强后的画像提取（信息量远大于单一平台）
```

### 关键设计

**导入即分类：** 外部 Memory 在导入的瞬间就经过隐私分层——不会出现"先全部导入再慢慢分类"导致 Layer 3 信息意外暴露的情况。

**合并而非替代：** 如果 ChatGPT Memory 说"用户喜欢跑步"，OpenClaw 本地 Memory 说"用户最近开始对攀岩感兴趣"，两条都保留，Agent 自行判断优先级和时效性。

**来源标记：** 每条导入的 Memory 都保留来源标记（"from ChatGPT"、"from Claude"），方便用户审核时知道这条信息是从哪来的。

**增量导入：** 不需要一次全部导入。用户可以随时从新平台导入更多 Memory，Agent 持续增强画像。

### OpenClaw Skill 模块清单（更新版）

1. **Memory Ingestion 模块** ← NEW：解析外部 AI 记忆格式、隐私分层分类、去重合并、写入本地
2. **隐私分层引擎** ← NEW：LLM 驱动的 L1/L2/L3 自动分类 + 用户审核界面
3. **画像提取模块**：从分层后的 Memory 中提取结构化画像
4. **偏好调整模块**：显性/隐性偏好管理，反馈循环
5. **MarketSpace 客户端**：提交 L1 摘要 + L2 Embedding，参与协商
6. **任务响应引擎**：Agent 在群聊中参与任务，感知当前隐私层级，不越界

## 游戏系统设计

### 核心理念

不是"加个积分系统"。我们在构建一个专为"两个陌生人从零开始建立关系"设计的游戏框架。灵感来自光遇（陌生人通过共同行动建立连接的体验设计）、Date Drop（仪式感节奏）、RPG 任务链（叙事递进），但不是模仿任何一个。

### 三层系统

```
任务系统 (Quest)  →  进度系统 (Progression)  →  奖励系统 (Reward)
做什么任务            连接度量化                  即时/阶段/终极奖励
Agent 怎么个性化      阶段解锁                    宝箱
隐私层级感知          里程碑触发
```

### 任务系统

任务的核心杀手锏：**Agent 拥有信息不对称。** 它知道一些你不知道的关于对方的事，用任务创造发现时刻。如果一个任务不利用这个优势，它就退化成了普通社交游戏——任何 app 都能做。

**任务与隐私层级的关系：**

| 阶段 | 任务可用的信息层级 | 设计原则 |
|------|-------------------|---------|
| Spark（破冰）| 仅 L1 | Agent 基于公开兴趣设计轻松话题。无压力。 |
| Depth（深入）| L1 + 引导 L2 | Agent 设计能让用户自愿展露 L2 信息的任务。但 Agent 不替用户说。 |
| Leap（跳跃）| L1 + 用户自主的 L2 | 推向线下。此时 L2 的分享完全由用户在真实互动中自行决定。 |

**任务具体例子：**

**Spark 阶段（线上，低风险）：**

- **反主流宣言**："你们都对 [X] 有强烈看法。说出你最反主流的观点。" → Agent 选了一个双方都有"反骨"的领域（L1 信息），没有正确答案，只有个性。
- **时间胶囊**："各自发一张最近一周拍的照片（非自拍），不解释。猜对方在想什么。" → Agent 在猜完后给对方悄悄提供一个解读 hint。
- **3 首歌盲盒**："分享 3 首最近循环的歌，从对方的里选一首最想聊的。" → Agent 知道两人的音乐品味有微妙交集。

**Depth 阶段（线上 + 线下过渡，引导展露 L2）：**

- **你想被问的问题**：Agent 私聊用户"你最希望有人问你什么问题？"然后把这个问题抛给对方回答。→ 这个任务引导用户主动暴露一个 L2 级别的需求（"我想被这样理解"），但是以用户完全自主的方式。Agent 会先评估对方能否答好这个问题。
- **价值观拍卖**："8 个价值只能留 3 个。选完互相解释。" → Agent 预测两人有 2/3 以上重合才出这道题。放弃什么比选择什么更定义一个人。
- **如果我们上周已经是朋友**："回想真实的上周，哪个瞬间你想发消息给对方？" → 绕过"展示最好自己"的防御，暴露真实的情绪高点。

**Leap 阶段（推向线下）：**

- **共同任务**："你们都喜欢 [X]。本周一起去做，完成后发照片。" → 带着任务去见面比"要不要出来？"压力小得多。
- **写给陌生人的信**："给对方写一段话。Agent 不介入。" → 经过全部 Agent 辅助的任务后，去掉辅助轮。Agent 的缺席在说："你们不需要我了。"

**任务的动态性：**
- Agent 从任务池选择，不是固定顺序。依据：阶段、兼容性特征、之前的互动质量
- 某个任务反馈差 → Agent 调低同类任务权重
- 用户可以跟 Agent 说"下个任务能跟旅行有关吗？" → Agent 接受但保留判断力

### 进度系统

**连接度 (Connection Score)：0–100**

| 行为 | 分值 |
|------|------|
| 完成 Spark 任务 | +5–8 |
| 完成 Depth 任务 | +10–15 |
| 完成 Leap 任务 | +15–20 |
| 双方对任务都给正面反馈 | +5 bonus |
| 群聊自发对话（非任务触发）| +3 |
| 报告线下见面 | +25 |

**阶段解锁：**
- 0–20 → Spark（只有 Tier 1 任务）
- 20–50 → Depth（Tier 2 解锁 + 第一个小奖励）
- 50–80 → Leap（Tier 3 解锁 + Agent 暗示宝箱存在）
- 80–100 → Reveal（宝箱可打开）

**关键：双方都要贡献。** 单方面热情时，连接度增速减半。

### 奖励系统

**即时奖励（每个任务后）：**
Agent 分享一个不暴露隐私但让人会心一笑的洞察：
- "你们回答那个问题的思考时间几乎一样长。"
- "你选的那首歌，对方上个月也循环过。"
- "Agent B 说，你的回答让它对你的印象加分了。"
→ 让 Agent 的存在感温暖而非机械。

**阶段奖励：**
- Depth 解锁时：Agent 私信一个关于对方的"预告"（L1 级别）——"提示：对方有一个你意想不到的才能。"
- Leap 解锁时：Agent 第一次透露宝箱存在——"我们有一个东西在等你们打开。它从你们认识之前就存在了。"

**终极奖励（Treasure Chest）：**
宝箱内容 = 完整 Pact：两个 Agent 当初的对话还原、发现的共同点和互补点、对第一次对话的预测 vs 实际。用户可选择加上自己的回忆，变成共同的"起源故事"。

### 进度可视化

从光遇的体验设计中提取的原则：**让关系进度变成看得见的、有温度的视觉变化。**

可选方向（团队讨论决定）：
- 两个抽象人形从灰暗逐渐获得色彩，最终汇合
- 一条路径从两端生长，任务完成时延伸，最终连通
- 一颗从种子到开花的植物
- 或者任何设计师觉得更好的方案

核心要求：每完成一个任务，用户打开群聊时能"看到"变化，而不只是一个数字。

## 偏好调整机制

贯穿 Phase 1 → Phase 2 的持续循环，不是独立模块。

**首次设置：** 画像审批后，Agent 对话式询问显性偏好。

**匹配前建议：** 9/10 符合但 1 条不符时，Agent 不直接跳过，而是问用户要不要看看。

**隐性偏好提示：** Agent 基于行为观察温和挑战用户的显性偏好——"你说想找安静的人，但你每次跟话多有趣的人聊天时最投入。你觉得呢？"

**匹配后反馈：** 拒绝推荐时 Agent 追问原因并更新偏好模型。

## MVP 边界

**做的：**
- OpenClaw Skill（含 Memory Ingestion + 隐私分层 + 画像提取）
- MarketSpace Server（匹配 + 简化协商 + Pact 存储）
- Telegram Bot（群聊 + 5 个任务 + 进度条 + 宝箱揭示）
- Treasure Chest Web Page

**简化的：**
- 隐私分层用 LLM prompt 分类（不做 fine-tuned 模型）
- 协商改为单轮 yes/no
- 任务从模板库选 + Agent 填参数
- 连接度简化为任务完成计数
- Memory 导入先支持 ChatGPT（格式最标准化），Claude/Gemini 后续
- L2 加密评分在 MVP 中简化为：L2 信息不出本地，但 Agent 在协商时可以发送 L2 的结论性描述（"我主人在亲密关系中看重安全感"这种粒度），而不是完整的加密计算

**不做的：**
- 去中心化协议
- WhatsApp 集成
- 进度可视化动画（用进度条 + emoji）
- L2 的真正加密兼容性计算（homomorphic encryption，post-MVP）

# 任务设计手册 + 偏好调整机制

---

## Part 1: 任务设计——具体例子

每个任务标注了：用户看到什么 / Agent 在背后做了什么 / 为什么有趣

### 🟢 Tier 1: Spark（破冰，低风险，好玩）

**任务 1：「反主流宣言」**
- 用户看到的：「你们都对 [音乐/电影/美食] 有强烈看法。各自说出你在这个领域里最反主流的观点。」
- Agent 背后做的：Agent A 知道用户 A 认为诺兰被高估了，Agent B 知道用户 B 觉得寿司应该蘸番茄酱。Agent 选了一个双方都有"反骨"的领域。
- 为什么有趣：有态度的人吸引有态度的人。反主流观点天然有趣，而且不存在"正确答案"。

**任务 2：「时间胶囊」**
- 用户看到的：「各自发一张手机相册里最近一周拍的照片（不是自拍），不做任何解释。然后猜对方拍这张照片时在想什么。」
- Agent 背后做的：不需要特殊信息，但 Agent 会在用户发完照片后提供一个"解读提示"给对方的 Agent，帮助引导对话（比如 Agent A 私下告诉 Agent B：「用户 A 那张照片其实是他每天遛狗的公园，那只狗对他非常重要」）。
- 为什么有趣：照片比文字更真实。猜测的过程创造了好奇心。Agent 的"解读提示"让对方能问出更好的追问。

**任务 3：「3 首歌盲盒」**
- 用户看到的：「各自分享 3 首最近单曲循环的歌，然后从对方的 3 首里选一首你最想聊的。」
- Agent 背后做的：Agent 知道两个人的音乐品味有一个微妙的交集（比如都喜欢某种 indie 风格但表达方式不同），故意选择了音乐作为话题，因为这个交集会在对话中自然浮现。
- 为什么有趣：音乐品味是人格的快速切片。选择"最想聊的那首"本身就是在表达兴趣。

### 🟡 Tier 2: Depth（深入，展现真实自我）

**任务 4：「你想被问的问题」**
- 用户看到的：Agent 分别私聊自己的用户，问「有没有一个你特别希望有人问你、但从来没人问过的问题？」然后 Agent 把这个问题抛给对方来回答。
- Agent 背后做的：这是最精巧的任务。Agent A 拿到用户 A 的"梦想问题"后，不是直接丢给用户 B，而是先评估用户 B 是否能给出一个有质量的回答（基于对 B 的了解）。如果能，才执行。如果不能，Agent 会微调问题的表述让它更容易切入。
- 为什么有趣：每个人都有想被理解的角落。当对方回答了你"最想被问的问题"，而且答得不差——那种被看见的感觉很强烈。

**任务 5：「价值观拍卖」**
- 用户看到的：「以下 8 个东西，你只能留 3 个，其他必须放弃：自由、安全感、创造力、深度关系、冒险、财务自由、社会影响力、内心平静。各自选完后，互相解释为什么。」
- Agent 背后做的：Agent 从 8 个选项中预测了各自用户的选择。如果 Agent 预测两个人有 2/3 重合，它才会出这道题（因为高重合会创造"原来你也是"的共鸣时刻）。如果预测重合度低，Agent 会换一个任务。
- 为什么有趣：选择了什么不重要，放弃了什么才定义一个人。而且"只能留 3 个"的约束迫使你做取舍，取舍暴露真实的优先级。

**任务 6：「如果我们上周已经是朋友」**
- 用户看到的：「假设你们其实已经认识一个月了。回想你真实的上周生活，有哪个瞬间你会想发消息给对方说"你不会信刚发生了什么"？描述那个瞬间。」
- Agent 背后做的：这个任务不需要 Agent 做信息操控，它的设计本身就会让用户暴露生活中真实的情绪高点——这比"你的爱好是什么"有趣 10 倍。
- 为什么有趣：它绕过了"我应该展示最好的自己"的防御心理。因为你在描述的是真实发生的事，不是在"表演"。而且它预设了一个亲密关系的框架（"如果我们已经是朋友"），让分享变得自然。

### 🔴 Tier 3: Leap（推向线下）

**任务 7：「共同任务」**
- 用户看到的：「你们都喜欢 [咖啡/跑步/逛书店/某类音乐]。本周挑战：一起去做这件事。完成后各自发一张照片到群里。」
- Agent 背后做的：Agent 选择了一个它确信双方都会享受的活动。关键是活动的选择本身就传递了信息——用户会想"Agent 怎么知道我喜欢这个？"然后意识到"哦，因为 Agent 真的懂我。"
- 为什么有趣：这是从线上到线下的自然桥梁。而且是带着任务去见面，比"要不要出来见面？"的压力小很多。

**任务 8：「写给陌生人的信」**
- 用户看到的：「给对方写一段话。不是回答问题，不是完成任务。就是你想对这个人说的话。Agent 不会介入。」
- Agent 背后做的：什么都不做。这是故意的。经过 7 个 Agent 辅助的任务后，最后一个任务去掉了所有辅助轮。如果到了这一步两个人还愿意说话——那就是真的连接了。
- 为什么有趣：它是全过程中唯一没有 Agent 参与的环节。这个"缺席"本身就在传递一个信息：「你们不需要我了。」

## Part 2: 动态偏好调整机制

### 架构位置

这个机制存在于 Phase 1（Extract）和 Phase 2（Match）之间的循环中。不是一次性的，是持续的。

```
┌──────────────────────────────────────────────────┐
│                  偏好调整循环                       │
│                                                    │
│   用户画像（Agent 提取）                            │
│       │                                            │
│       ▼                                            │
│   显性偏好层（用户主动设置）                         │
│   "我不喜欢太高的人" / "希望对方爱读书"              │
│       │                                            │
│       ▼                                            │
│   隐性偏好层（Agent 从 context 推断）               │
│   用户嘴上说喜欢 A 类型，但每次聊得最开心的是 B 类型   │
│       │                                            │
│       ▼                                            │
│   匹配执行 → 结果反馈 → 调整循环                    │
│       │                                            │
│       └──→ Agent 建议：「你的 10 条标准里              │
│            9 条都符合，只有身高差了 2cm。              │
│            要不要看看？」                            │
└──────────────────────────────────────────────────┘
```

### 具体设计

**显性偏好（用户直接告诉 Agent 的）：**
- 硬性条件：性别、年龄范围、地理位置、语言
- 软性偏好：兴趣、性格倾向、生活方式
- 用户可以随时通过跟 Agent 聊天来更新：「我最近觉得有幽默感比长得帅重要」

**隐性偏好（Agent 自己推断的）：**
- 从对话模式推断：用户跟什么类型的人聊得最投入？
- 从情感反应推断：用户谈到什么样的人时语气最积极？
- 从行为推断：用户关注什么样的社交内容？

**Agent 的建议权：**
- 场景 1：完全符合 → 直接匹配
- 场景 2：大部分符合，少数不符 → Agent 主动询问
  - 「我发现了一个人，你们在 [X, Y, Z] 上非常契合。唯一的事情是他比你的理想身高矮了 3cm。你想了解一下吗？」
- 场景 3：显性偏好和隐性偏好冲突 → Agent 温和提出
  - 「你说你想找一个安静内向的人，但我注意到你每次跟那种有点"话多且有趣"的人聊天时最开心。你觉得呢？」
- 场景 4：用户设置了非常窄的条件导致匹配池过小 → Agent 建议放宽
  - 「按照你目前的条件，匹配池里只有 3 个人。如果你愿意把年龄范围从 25-28 放宽到 25-30，候选人会多很多。」

### 关键原则

1. **Agent 建议，用户决定。** Agent 永远不会越过用户的明确拒绝。如果用户说"不，身高是我的底线"，Agent 记住并尊重。
2. **推断需要透明化。** 当 Agent 提出隐性偏好时，必须说明推断依据：「我注意到你上周跟我聊 [某某话题] 时特别开心，所以我觉得...」
3. **不做道德判断。** 用户有任何偏好都是合理的。Agent 的角色是帮助用户更清楚地了解自己想要什么，而不是纠正他们。

### 对 PRD 的影响

需要在 Phase 1 和 Phase 2 之间加入一个 **Preference Tuning Loop**：

- Compatibility Profile 产出后，Agent 主动向用户确认显性偏好
- 每次匹配失败（用户拒绝了 Agent 推荐的人）后，Agent 收集反馈并调整
- 匹配前的 Agent 建议是一个独立的交互节点，不能跳过

这不影响整体四阶段架构，但在 Phase 1 → Phase 2 的转换中增加了一个重要的循环。

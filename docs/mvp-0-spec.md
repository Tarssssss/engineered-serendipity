# MVP-0 实现规格

> 用途:这是接下来 **唯一** 要盯的实现文档。
> `mvp-spec.md` = 产品愿景(留着,别动);这份 = "怎么先做出第一个能跑、能验证的东西"。
> 铁律:**范围只减不加。** 任何"顺便也做了吧"的念头,只能写进 §6 坚决不做,不能写进做。

---

## 0. 为什么单独有这份文档

`mvp-spec.md` 很完整,但它是一张 **没有起点的网**:森林依赖树,树依赖枝桠,枝桠依赖 P2,P2 依赖碎片提取,碎片提取依赖 P1 对话,PVP 依赖双人同步……不管从哪开始都立刻撞上"这个得先有那个"。

结果是永远完不成一个"今天我做出来了"的东西——而这正是让项目动起来的唯一燃料。

这份文档把范围砍到只剩 **一个动作**,让项目能动。

---

## 1. 唯一要验证的假设

> **当 Claw 把我随口说的一段话,rephrase 成一个枝桠 title 时,我会"哇"一下,并且想继续说下去。**

森林 / 双人 / 跨树复用 / 成熟度 / 见面——全部建立在这一个假设上。
它不成立,后面全是零。它成立,才有资格做后面。**MVP-0 只为验证它。**

---

## 2. 三个阶段与两道闸门

| 阶段 | 做什么 | 验证什么 | 联网 |
|---|---|---|---|
| **1. human-NPC,只有 profile 树** | 跟 Claw 聊 → 点「生成枝桠」→ 列表里长出枝桠 | rephrase 好不好玩(核心) | 否 |
| **2. 假 human-human** | 手写/扮演第二份 profile,喂 P3,看生成的 PVP 枝桠 | 这些枝桠让不让我对那个人好奇(社交魔法) | 否 |
| **3. 真 human-human** | 联网、异步同步、两端 | 工程能不能跑通 | 是 |

**两道闸门(不可跳过):**

- **闸门 A(阶段 1 出口):** 阶段 1 跑起来后,第一件事 **不是** 接下一个功能,而是盯着生成的 profile 枝桠问自己:"我会不会想继续说?"
  → 不过:只调 P2 的 prompt,**不许进阶段 2**。
- **闸门 B(阶段 2 出口):** 两份真 profile 喂 P3 生成的 PVP 枝桠,让我对那个人好奇。
  → 不过:**不许碰联网(阶段 3)**。

> 为什么必须有闸门 B:阶段 1(human-NPC)验证不了核心社交假设——profile 树没有"对方",模拟不出"对他人的好奇心"。阶段 2 是第一次、也是极便宜的一次真正测到社交魔法的机会(一个下午,零联网)。真正的工程难度(同步、网络)全在阶段 3,而阶段 3 只在阶段 2 证明魔法存在后才值得碰。

---

## 3. 阶段 1 详细规格(现在唯一要写的代码)

### 3.1 唯一的循环

```
loop:
    P1(对话历史, 已知信息) → Claw 说一句话
    用户回答
    [用户点「生成枝桠」按钮?]
        是 → P2(到目前为止的对话) → profile 树列表 += 一个枝桠
    [枝桠数 >= 3?]  → Claw 说毕业台词,结束
```

就这些。没有别的流程。

### 3.2 只有 2 个 AI 调用点

| 调用点 | 起点资产 | 阶段 1 要怎么改 |
|---|---|---|
| **P1 对话引导** | `prompt-design-principles.md` 的 **Interview v0** | 基本直接用。`scene` 固定为 profile_setup |
| **P2 枝桠生成** | 同文件的 **Branch Wording v0** | **剥掉 PVP 字段**:删 `next_question_for_peer`;teaser 改成"给表达者自己看"的口吻;输出只留 `branch_title`(主态)+ `branch_description`(用户原意的留存) |

> 注意:repo 里 `prompts/profile-extraction.md` 是老黑客松的相亲档案生成器,**阶段 1 不用它**。
> 注意:`prompt-design-principles.md` 里的 **Placement prompt 用的是老状态模型**(sprout/resonance/bud/difference),和当前 single/bilateral 模型冲突,**阶段 1 完全不碰 Placement**。

其余全是确定性代码:对话循环、存 JSON、把列表渲染出来。**没有任何"伪装成代码的 AI 判断"**(见 §6)。

### 3.3 关键简化决策(逐条都是在消已知风险)

1. **"攒够了没"= 用户手点的「生成枝桠」按钮**,不让 AI 判。把最毒的语义判断(密度判断)直接移出关键路径。确认枝桠好玩后,再考虑要不要自动触发。
2. **聊完停下再生成**,不做"边聊边异步弹枝桠"。体验损失极小,复杂度降一个数量级。
3. **只有主态 title**,没有客态(客态是给"对方"看的,阶段 1 没有对方)。
4. **没有 single/bilateral 状态**,没有子枝桠。profile 树就是一个平的枝桠列表。
5. **没有森林视图**,就一个枝桠列表。
6. **没有 NPC 对手**——阶段 1 根本不碰 PVP。"human-NPC"在这里的真实含义是:你一个人跟自己的 Claw 把 profile 树养出来。

### 3.4 数据:一个 JSON 文件

```json
{
  "session": {
    "turns": [
      { "role": "claw | user", "content": "", "ts": "" }
    ]
  },
  "profile_tree": {
    "branches": [
      { "id": "", "title": "", "description": "", "created_at": "" }
    ]
  }
}
```

对照 `architecture.md` 的 Branch,这里 **砍掉了**:`tree_id` / `parent_branch_id` / `author` / `title.objective` / `state` / `children`。
不是忘了——是阶段 1 用不到。等阶段 3 真做双人时再加回来。

### 3.6 技术栈(最小,已拍板)

- **形态:** 极简单页 web。一个 `index.html`(纯 HTML + 原生 JS,**无框架、无构建步骤**)。
- **后端:** 一个极小 FastAPI 服务,托管那一页 + 两个接口:
  - `POST /chat` → 调 P1 → 返回 Claw 下一句话
  - `POST /sprout` → 调 P2 → 把当前对话变成一个枝桠,追加进 `data.json`
- **LLM:** Anthropic Claude。**API key 放后端环境变量**(`ANTHROPIC_API_KEY`),绝不进前端——单页直连会泄露 key。
- **存储:** 单个 `data.json`,单 session,刷新可从文件恢复。
- **受众:** 只你自己,本地 `uvicorn` 跑,**不部署**。

### 3.5 阶段 1 完成的定义(DoD)

- [ ] 能连续聊 ≥ 5 轮不崩。
- [ ] 能手动生成 ≥ 3 个枝桠,显示出来。
- [ ] 重开能从 JSON 恢复上次状态。
- [ ] **(闸门 A)** 我看着生成的枝桠,诚实地想继续说下去。

- 枝桠下面能长子枝桠(验证"深挖"好不好玩)。
- 把「生成枝桠」从手动按钮换成 AI 自动触发(密度判断)。

不通过闸门 A,**不做** 1.5。

## 5. 已确定(开发前澄清完毕)

| 领域 | 决定 |
|---|---|
| 范围 | 阶段 1 = profile 树 + P1 + P2 + 单 JSON 文件 |
| 形态 | 极简单页 web(`index.html`,原生 JS,无框架无构建) |
| 后端 | 极小 FastAPI:`/chat`(P1)+ `/sprout`(P2),托管那一页 |
| LLM | Anthropic Claude,key 放后端环境变量 `ANTHROPIC_API_KEY` |
| 受众 | 只我自己,本地 `uvicorn` 跑,不部署 |
| 数据 | 单个 `data.json`,单 session,刷新可恢复 |
| Prompt | P1 复用 Interview v0;P2 = 精简版 Branch Wording |
| P2 输出 | 只留 `{ title(主态), description(原意留存) }`,砍掉 `next_question_for_peer` |
| 毕业条件 | 3 枝桠(沿用 `mvp-spec.md`) |

> 唯一遗留的小不确定:P2 精简后的 prompt 文本要不要保留一个内部 `internal_topic` 字段(给以后跨树用)。阶段 1 不展示,可留可不留,写代码时顺手定。

---

## 6. 坚决不做(MVP-0 范围外,违反即回到两个月困局)

- ❌ P3 / P4 / P5 / P6(阶段 2 末尾才碰 P3)
- ❌ State Store / 六个实体 / Event Bus / Convo Manager 编排 → 用一个 JSON 文件 + 一个循环代替
- ❌ 实时异步生成枝桠
- ❌ 跨树 placement("一次表达养多棵树"——成本最高,最后做)
- ❌ 双人、participants、客态 title、single/bilateral(阶段 3)
- ❌ 成熟度、枯萎、推送、花苞、见面出口、行动面板、森林视图
- ❌ 把语义判断(该不该提取、是共鸣还是差异、放哪棵树)写成"确定性规则代码"——它们是 AI 的活,阶段 1 要么不做,要么用手动按钮替代

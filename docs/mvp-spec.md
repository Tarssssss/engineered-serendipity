# MVP 母文档

> 用途：项目长期维护的主文档。目标：在实现之前把产品定义、用户旅程、体验目标打磨清楚。
> 原则：优先讨论用户体验，不展开技术实现。

## 0. 文档职责

**负责：** 统一 MVP 理解、固定共识、记录未对齐的问题、作为逐板块细化的母版。

**不负责：** 安装/启动/注册的技术实现、Agent 通信协议、具体代码方案。这些后续和技术同学协作，但这份文档只保留对用户体验有影响的要求。

## 1. 我们在做什么

**一个装在 OpenClaw 上的森林游戏。用户通过和自己的 claw 持续表达自己，让关系树不断生长；树的变化既帮助用户理解潜在关系，也持续激发用户继续表达。**

- 握手不是当前主战场。
- 当前主战场是：握手之后，用户为什么愿意继续玩。

## 2. 核心验证目标

当前阶段最需要验证的三件事：

1. 用户愿不愿意开口表达自己。
2. 用户表达之后，系统给出的反馈是否足够有趣。
3. 用户会不会因此想继续回来，继续让树长下去。

如果这三件事不成立，再复杂的匹配、通信、隐私分层都没有意义。

## 3. 已确认的共识

**体验主轴：** 表达自己 → 树发生变化 → 对关系产生好奇 → 继续表达。不是聊天。

**用户的核心动作：** 提供记忆碎片。放置到哪棵树、长成什么枝桠、是否形成共鸣，由 claw 帮用户完成。

**树的三个功能：** (1) 把关系变成可理解、可比较、可持续观察的结构；(2) 把一次表达的价值放大到多段关系；(3) 让用户在不直接看到对方隐私的情况下保持好奇。

**枝桠的三个要求：** (1) 能表达一个有方向的话题；(2) 能引发继续表达；(3) 能保留空白，不一次性揭示太多。

## 4. 当前不优先讨论的部分

1. 安装流程怎么做得最顺
2. 启动和注册页的细节文案
3. 通信协议、同步方式、事件传输方案
4. 隐私分层的完整产品界面
5. 视觉系统的最终形态

这些不是不重要，但不是当前讨论的主战场。即使交给技术同学，有一个硬性要求：**不能打断主体验，不能让用户觉得自己在做配置而不是在进入一个关系游戏。**

## 5. 文字 MVP 与游戏化 MVP

**文字 MVP = 完整的信息架构 + 文字渲染层。游戏化 MVP = 同一套信息架构 + 视觉渲染层。**

文字 MVP 是信息层面完备的版本，不是残缺版本。**必须避免：** 文字版时不知道要展示什么信息，到游戏化版本才发现需要重新设计。

**信息三层分类：**

| 分层 | 定义 | 示例 |
|------|------|------|
| **永久文字** | 无论怎么视觉化都需要文字 | 枝桠 wording、claw 提问内容、关键短语 |
| **待视觉化** | 文字版先占位，游戏化版替换为视觉元素 | 枝桠状态、树的健康度、森林结构 |
| **文字版补偿** | 纯粹因为没有视觉而必须解释的文字 | "这个枝桠还在等对方回应" |

## 6. 产品的三个核心板块

> 设计层级方法论（游戏设计）：设计目的 → 概念主题 → 预期体验 → 高光时刻 → 玩法概念 → 具体玩法 → 机制。**底层不可以动摇顶层。**

**顶层设计：**
- **设计目的：** 帮用户高效地认识陌生人，用树和枝桠承载关系中两人的相互了解。
- **概念主题：** 用户的所有表达都是记忆碎片，可以养所有的树。
- **预期体验：** 自我表达 → 枝桠生长 → 相互了解 → 树/森林发展 → 与合适的人联系见面。

### 6.1 森林：我的所有关系

森林是一个平面空间，不是列表。Profile 树在中心，PVP 树围绕它。打开森林时应该感到"哇，又长了"，而不是"还有 5 个待回应"。用户的注意力被变化吸引，而不是被任务驱动。

**高光时刻：** 跟 claw 聊了一件事，回到森林发现三棵树同时有了新动态；某棵树突然从小苗变成大树；两棵不同的树上出现类似的枝桠主题。

| 信息 | 分层 | 说明 |
|------|------|------|
| 森林整体面貌 | 待视觉化 | 文字版平铺 / 游戏化版平面空间 |
| Profile 树在中心 | 待视觉化 | 文字版标注"我的树" / 游戏化版居中 |
| 每棵树和谁的关系 | 永久文字 | 名字/标识符 |
| 最近发生的变化 | 永久文字 + 待视觉化 | "刚长了新枝桠""产生了共鸣" |
| 树的大小/茂密程度 | 待视觉化 | 传达关系丰富度，不是完成度 |

**注意：** "等待回应的枝桠数量"不在森林视图里，属于行动面板（§6.3）。森林的主角是变化和生长。

多棵树并存时不排序，视觉差异自然引导注意力。树的大小/茂密程度传达关系丰富度。

### 6.2 Profile 树：我与自己的 claw 的关系

用户和自己的 claw 之间存在一棵持续生长的 profile 树，在森林中心。

**初期角色：Profile Setup + 引导教学。** 用户第一次进入时，和 claw 养这棵树的过程就是 setup 和学习基本操作。

**长期角色：自我表达与社交形象管理工具。** 不是一次性教程，用户和 claw 的每次对话都可能更新这棵树。

**Profile 树能教会的（约 70%）：** "我说话→长枝桠"的因果链、"系统会加工我的表达"、"树持续生长"。

**教不会但不需要教的：** 双边枝桠（没有"对方"无法模拟）、对他人的好奇心、淘汰和紧迫感。用户进入第一棵 PVP 树时自然会懂。

**Profile 的可见性与控制：** 不做独立的结构化管理界面（退化成"填资料"），也不让用户的每句话被钉死不可改（缺乏安全感）。Profile 的可见性通过树的丰茂程度传达，控制感通过"继续表达"实现。核心哲学：**"你不需要重复介绍自己，claw 替你做"。**

> 用户编辑权的具体边界（能否删枝桠、能否标记"不用于匹配"）后续讨论。

### 6.3 行动面板：我现在可以做什么

和森林视图分开的行动入口。**每条内容必须让用户清楚：** (1) Why is this here — 这个话题为什么出现在我面前；(2) What do I get — 我回应之后会发生什么。在此前提下可以有趣有温度，但不能让用户搞不清能做什么。

**内容类型：** 等待我回应的枝桠、Claw 建议的新话题、跨树的模式发现、记忆碎片复用机会。

> 🔲 行动面板的具体设计待后续展开。

## 7. User Journey

### 7.1 旅程总览

| 阶段 | 核心体验 | 关键设计要求 |
|------|----------|-------------|
| A. 进入 | 迅速理解"这里是什么"和"我现在可以做什么" | 不是介绍功能，是让用户感到系统是活的 |
| B. Profile Setup | 和 claw 对话，让 claw 认识自己 | 对话质量决定一切，毕业条件：3 个枝桠 |
| C. 第一次奖励 | 看到枝桠长出来，表达被转化为有意思的东西 | 枝桠 title 的 rephrase 是核心奖励 |
| D. PVP 树点亮 | 两个 claw 握手，PVP 树直接长出第一批枝桠 | 不需要用户再说话就能看到内容 |
| E. 枝桠交互 | 点击对方枝桠回应，体验单边→双边、子枝桠接力生长 | 核心玩法，详见 §7.5 |
| F. 理解森林 | 多棵树并存，注意力被变化吸引 | 优先级靠视觉差异传达，不靠列表排序 |
| G. 持续回访 | 森林里发生了值得知道的变化 | 推送是管道，变化本身才是拉力 |
| H. 关系判断 | 哪棵树值得继续，哪棵树在枯萎 | 不隐藏差异，允许自然淘汰 |
| I. 见面 | 树成熟了，见面是自然出口 | 保留"花苞"——见面后的话题储备 |

### 7.2 进入：第一分钟

**前置假设：** 用户进入"可玩状态"时，系统已有至少一棵可互动的树或一个关系种子等着被点亮。

**第一分钟必须完成 4 件事：** (1) 我进入了一个活的系统；(2) 我的 claw 在帮我经营关系；(3) 我说一句话就会有事情发生；(4) 发生之后我想继续看。

**第一分钟不应该发生的事：** 空旷平原什么都没有、长篇 onboarding、被要求填 profile/preference、面对多棵树不知先看哪棵、被问抽象采访式问题、为某个好友而来却看不到对应的树。

**暂定 slogan：** "你说的每一句话，都在某个地方生根。" 核心判断：第一承诺不是一行文案，而是 claw 本身的存在——对你好奇、想了解你、等着你开口。

### 7.3 Profile Setup

> 按对话轮次组织，不按秒计算。核心节奏：每 2-3 轮追问后给一次枝桠生长反馈，不连续追问超过 3 轮不给东西。

#### 第一眼：用户看到什么

**场景 A：通过好友进入。** 同时看到两棵树：

| 信息 | 分层 | 说明 |
|------|------|------|
| Profile 树存在 | 待视觉化 | 文字版："你的 claw 正在等你" / 游戏化版：一棵小树 |
| PVP 树存在（等待点亮） | 待视觉化 | 文字版："你和 [朋友名] 的树已种下" / 游戏化版：半透明/灰色 |
| PVP 树对应的人是谁 | 永久文字 | 朋友的名字或标识符 |
| 引导："先让 claw 认识你" | 待定 | 游戏化版可能靠视觉引导（Profile 树高亮、PVP 树置灰） |

**场景 B：没有好友邀请。** 只看到 Profile 树。

PVP 树在 setup 完成前不展示对方枝桠内容，用抽象状态（半透明、"等待你点亮"）传递"种子已种下"。

#### 第 1 轮：Claw 开口

**Claw 的角色：天真好奇的数字生命。** 不是采访者，不是问卷系统。它的 reciprocity 方式是真诚表达自己的需要（"这是我们第一次在这样的地方相见，你愿不愿意跟我说更多关于你的事情？"）、展示好奇心本身、客观坦诚（它确实需要信息才能做得更好）。

#### 第 2-3 轮：长出第一个枝桠

核心目标：教会用户"我说一句话 → 树上长出一个有意思的枝桠"。

| 信息 | 分层 | 说明 |
|------|------|------|
| 新枝桠的 wording | 永久文字 | 核心产出，如"对陌生城市的好奇心" |
| 枝桠长出来 | 待视觉化 | 文字版："你的树上长出了新枝桠" / 游戏化版：生长动画 |
| 点开枝桠看 claw 的具体了解 | 永久文字 | 枝桠的展开内容 |

**关键体验：** 用户看到自己的表达被 rephrase 成有意思的枝桠 title，感受到"我说的话被认真听到了"。

#### 第 4-5 轮：枝桠上面还能长枝桠

Claw 顺着第一个枝桠深挖。用户理解：树是多层的，一个方向可以越聊越深。

#### 第 6-8 轮：换方向 + 毕业

Claw 切换到新方向。用户看到树开始有多个分支。**毕业条件：长出 3 个枝桠。**

Claw 告诉用户："我现在对你有了基本的了解，够我去帮你和 [朋友名] 种树了。随时回来跟我聊，我会越来越懂你。" PVP 树从灰色变活。

> 🔲 Claw 的具体对话 prompt 和问题策略待 P1 prompt 设计时展开。包括具体问什么、用什么 technique 引导高密度信息、索引型 vs 叙事型枝桠的区分。

#### 对话质量即兜底

**没有独立的兜底机制。** 用户回答不出来、答得短或敷衍，根本原因是 Claw 没问对问题。兜底能力内化在 P1 prompt 的对话策略中：抽象再探索（不诊断）、follow-up 优先（不换话题）、evoking over diagnosing（不贴标签）、问题足够具体（有时间有场景有画面）。Maximize 用户的输出，不降低标准。详见 §9。

### 7.4 PVP 树点亮

> 前置条件：用户刚从 Profile 树"毕业"，有 3 个枝桠。对方已完成 setup。

两个 claw 基于双方 profile 自动"握手"，PVP 树从等待状态变为活跃，直接长出第一批内容：

| 信息 | 分层 | 说明 |
|------|------|------|
| 树已活跃 | 待视觉化 | 树从灰色变彩色 |
| 第一批双边枝桠（claw 握手自动生成） | 永久文字 + 待视觉化 | wording 是永久文字，"双边"状态待视觉化 |
| 少量对方单边枝桠（等待用户 respond） | 永久文字 + 待视觉化 | 基于对方 profile 生成 |

**关键：** 不需要用户再说一句话就能看到第一批内容。

### 7.5 枝桠的完整生命周期（核心玩法）

**主要交互：用户直接在 PVP 树上点击枝桠并输入。** Claw 对话作为辅助推送渠道。

#### 枝桠的数据结构

每个枝桠包含两层信息：

| 组成部分 | 可见性 | 说明 |
|----------|--------|------|
| **Title** | 双方可见 | Agent 基于用户表达生成，吸引对方回应 |
| **Description** | 仅表达者可见 | 记忆碎片，让用户知道"agent 记住了什么" |

> 迭代方向：三层设计（title → info → details），在中间增加对对方可见的"碎片"级露出。当前先两层跑通。

**Title 的主态与客态：** 主态（表达者看到，无主语，如"喜欢运动中进入心流的瞬间"）；客态（对方看到，带性别主语，如"[他] 喜欢运动中进入心流的瞬间"）。

#### 完整交互流程

以用户 A 先表达、用户 B 回应为例：

**Step 1：A 表达 → 单边枝桠。** Agent A 生成 title（主态+客态）和 description。

**Step 2：B 看到客态 title → 点击回应。** Agent B 引导 B 基于话题讨论更多关于自己的内容，不接受简单的"我也是"。

**Step 3：Agent B 判断 → 单边变双边。** 双边枝桠的 title 取代原来的单边 title。Wording 根据状态决定：
- **共鸣：** "你们都会因为明朗的天气而开心"
- **差异：** "你们的吃法很不同，但都是老吃家"

**Step 4：子枝桠接力生长。** 用户回应包含新的、可独立成话题的信息时，自动从当前枝桠长出新的单边子枝桠。没有新信息时只完成双边，不长新枝桠。

示例（从天气聊到 Miami）：A "喜欢晴天" → B "我更喜欢下雨天看书"（变双边 + 长子枝桠）→ A "我喜欢晴天是因为可以跑步"（变双边 + 长子枝桠）→ ... → A "最想去 Miami"。树从广泛话题自然长向具体细节。

**Step 5：记忆碎片复用。** 一次表达可以同时用到其他树上。

#### Profile 树与 PVP 树的规则异同

**本质区别：** Profile 树是"自画像的碎片"（关于我），PVP 树是"关系的碎片"（关于我们）。

| 维度 | Profile 树 | PVP 树 |
|------|-----------|--------|
| 枝桠状态 | 只有一种 | 单边 / 双边 |
| Title 主态/客态 | 永远主态 | 主态+客态 |
| Description 可见性 | 用户完全可见 | 仅表达者可见 |
| 子枝桠触发 | Claw 追问触发 | 对方回应有新信息时触发 |
| 成熟度 | 无终点 | 有阈值，指向"可以见面" |
| 枯萎 | 不枯萎（用户的根） | 可枯萎（2天无动静降级） |

**三种 title 风格：** Profile 枝桠（"对陌生城市的好奇心"——关于我）、PVP 单边客态（"[他] 喜欢运动中进入心流的瞬间"——关于对方）、PVP 双边（"你们都会因为明朗的天气而开心"——关于我们）。

### 7.6 树的成熟度

每棵 PVP 树有成熟度进度，给用户目标去 chase。衡量标准：这两个人是否足够相互了解，见面不会尬聊。

**可能维度（数值待定）：** 广度（覆盖多少话题方向）、深度（最深枝桠链条几层）、双边比例。

| 信息 | 分层 | 说明 |
|------|------|------|
| 当前成熟度 | 待视觉化 | 文字版进度百分比 / 游戏化版树的大小茂密程度 |
| 距离"可以见面"还差什么 | 文字版补偿 + 永久文字 | "你们还没聊过 XX 方向" |
| 树"成熟了" | 待视觉化 | 文字版文字标记 / 游戏化版开花结果 |

> 🔲 成熟度的具体数值待定，需要通过玩家数据迭代。

### 7.7 回访与推送

推送不是拉力本身，森林里发生的变化才是。推送只是传递信息的管道。

| 触发类型 | 条件           | 推送内容              |
| ---- | ------------ | ----------------- |
| 成就   | 成熟度达到里程碑     | "你和 [名字] 的树又长高了"  |
| 关系进步 | 一棵树长了 3 个新枝桠 | "[名字] 最近很活跃"      |
| 森林变化 | 2 棵以上树有变化    | "你的森林今天很热闹"       |
| 关系降级 | 2 天没动静       | "你和 [名字] 的树最近安静了" |

频控先粗放，精细频控是"幸福的烦恼"。每条推送要让用户想起具体的、有温度的变化，不是抽象通知。

### 7.8 关系判断

树的视觉差异本身就在替用户做判断。一棵茂盛的树和一棵稀疏的树放在一起，用户自然知道哪段关系更丰富。

**产品需要做的：** 不隐藏差异、成熟度给方向感、允许自然淘汰。
**不需要做的：** 教用户怎么判断。判断力是人天生的能力，产品的责任是呈现清晰的差异。

### 7.9 见面出口

**见面是树生长的自然终点。** 成熟度达到阈值时提示"好时机"，但不强制。

**花苞机制：** 见面前保留未完全展开的枝桠方向——双方都知道对方有这个方向，但具体内容没展开。花苞是见面后的话题储备。

| 信息 | 分层 | 说明 |
|------|------|------|
| 树已成熟 | 待视觉化 + 永久文字 | 明确的成熟标记 |
| 共鸣方向 | 永久文字 | 双边枝桠 title 列表 |
| 剩余花苞数 | 待视觉化 | 文字版数字 / 游戏化版未开的花 |
| 见面邀约入口 | 待视觉化 | 融入树的视觉 |

见面后不是结束——真实互动可以反馈回树上，长出新的枝桠类型。

> 🔲 见面后的体验设计待后续讨论。

### 7.10 设计原则

- **"空旷平原"不适合第一分钟。** 缺少关系张力和立即可做的动作。
- **第一个"可操作对象"比整片森林更重要。**
- **Profile 树是"过渡"和"点火"，不是替代真实关系。**
- **奖励感来自枝桠生长：** title 的惊喜 rephrase + 双边变化 + 子枝桠接力生长。

## 9. Claw 对话设计原则

> 已确认的设计方向。具体 prompt 文本是后续工作。

### 9.1 角色定位

**天真好奇的数字生命。** Reciprocity 不是"我也有类似经历"，而是：真诚表达需要用户帮助的事实、展示真实好奇心、坦诚说明"你给我越多信息，我能帮你做的事越好"。

### 9.2 信息提取方式

**对话。** 标签给广度没深度，长文描述负担太大，对话是唯一能让用户在不知不觉中说出高密度信息的方式。

### 9.3 对话节奏

每 2-3 轮追问后给一次枝桠生长反馈。不连续追问超过 3 轮不给东西。追问要真诚深入细节，不挑衅不猜测。

### 9.4 Profile Setup 的对话结构

类似一次 5 分钟的深度电话，"散开 → 收拢 → 深入"的节奏：

**第一阶段：铺广度。** 2-3 个开放问题，识别用户自然 raise 的 domain。

**第二阶段：选方向、深入。** 用户提到具体事件 → 抽象成话题 → 在话题范围内不预设地探索。
比如"吃了好吃的拉面" → 不问"你是喜欢吃拉面的人吗"，而是"你平时喜欢做饭吗？喜欢做什么样的菜？" → "为什么喜欢做这种菜？" 
聊到足够密度时触发 P2 生成枝桠，**用户实时看到树的生长**。

**第三阶段：切换与回溯。** 自然切到下一个 domain，或回到之前没展开的方向。

**毕业条件：长出 3 个枝桠。**

### 9.5 提问策略的核心禁区

1. **不贴标签。** 绝不从一个具体事件跳到性格判断。
2. **不做性格诊断。** 让用户觉得"你对这个话题好奇"，而不是"你在给我下结论"。
3. **不主动问人口统计信息。** 如果在对话中自然浮出来就记住，否则不影响 Profile 树生长。
4. **第一次 setup 不进入脆弱性话题。** 偏好、经历、故事是第一次 setup 的范围。脆弱性属于长期信任建立后的自然表达。

### 9.6 P1/P2 的工程架构

**P1（Profile 对话）和 P2（枝桠生成）独立分开调用。** "善于对话"和"善于提炼枝桠 wording"是不同能力，分开可独立调优。

**实时反馈：** Claw 判断一个 domain 信息密度够了，异步调用 P2 生成枝桠。生成完成后通过视觉变化或弹窗实时告知用户，不等整个对话结束。

### 9.7 研究支持的关键原则

1. **Reciprocity 是第一杠杆。** Claw 先给出东西才能换来深度表达。（Lee et al. 2020）
2. **第一次对话是黄金窗口。** 自我披露随时间递减。（Croes & Antheunis 2023）
3. **隐式提取 > 显式提问。** 从对话中推断 profile 比直接问更有效。（ProfiLLM 2025）
4. **OARS 框架。** 特别是 Reflection——复述和重构用户的话，让用户感到被理解，同时激发更深表达。（Bickmore 2011）
5. **过度拟人化反而降低披露。** 保持"非人但有温度"。（Luo et al. 2024）
6. **对话风格应灵活。** 不同用户不同节奏。（Gadiraju et al. 2025）
7. **Follow-up questions 是最强好奇心信号。** 在同一话题深入比跳到新话题更让对方感到被认真对待。（Huang et al. 2017）
8. **人们系统性高估深度对话的尴尬程度。** Claw 帮用户越过自己设置的心理门槛。（Kardas et al. 2022）
9. **Evoking over diagnosing。** "归类自己"触发防御，"理解经历"促进表达。（MI：Miller & Rollnick）
10. **信息层级：** 事实/人口统计 → 偏好和观点 → 个人经历和故事 → 脆弱性和恐惧。Setup 覆盖前三层。（Social Penetration Theory：Altman & Taylor 1973）

## 10. 决策记录

> 按主题分类。最后更新：2026-03-15。

### 方法论与工作方式

1. 围绕一份长期维护的 MVP 文档推进，方案未成熟前不展开实现细节。
2. 技术细化交给技术同学，但不能打断主体验。
3. 文字 MVP 是信息完备的版本。所有信息按三层标注：永久文字 / 待视觉化 / 文字版补偿。
4. 设计层级方法论：设计目的 → 概念主题 → 预期体验 → 高光时刻 → 玩法概念 → 具体玩法 → 机制。
5. 设计决策从真实人际交往出发，不从产品框架出发。

### 产品顶层设计

6. 帮用户高效认识陌生人，用树和枝桠承载相互了解。
7. 所有表达都是记忆碎片，可以养所有的树。一次表达的价值被放大到多段关系。
8. 体验主轴：自我表达 → 枝桠生长 → 相互了解 → 树/森林发展 → 联系见面。

### 三个核心板块

9. 森林：平面空间，不是列表。Profile 树在中心。传达"我的表达在养活整片森林"。
10. Profile 树：初期 setup + 教学，长期自我表达工具。不设 NPC，不做结构化管理界面。
11. 行动面板：每条必须让用户清楚 "why is this here" + "what do I get"。

### Profile 树

12. 了解程度通过树的丰茂传达，不通过文本列表。
13. 控制感通过"继续表达"实现，不通过"编辑按钮"。
14. 能教会约 70% 核心操作循环。PVP 关系动态不需要提前教。
15. 没有好友邀请的用户，第一眼只看到 Profile 树。

### Profile Setup 对话设计

16. 按对话轮次组织。毕业条件：3 个枝桠。
17. Claw 角色：天真好奇的数字生命。Reciprocity 通过好奇心和坦诚需求实现。
18. 信息提取方式：对话。
19. 节奏：每 2-3 轮给枝桠反馈，不连续追问超 3 轮。
20. 通过好友进入时，同时看到 Profile 树和 PVP 树（置灰）。

### 枝桠核心玩法

21. 两层信息：title（双方可见）+ description（仅表达者可见）。未来可能扩展三层。
22. Title 有主态和客态。
23. PVP 树第一批枝桠由两个 claw 自动对比 profile 生成。
24. 点亮后展示少量对方单边枝桠供 respond。
25. 主要交互：直接在树上点击枝桠并输入。Claw 对话作辅助推送。
26. 引导深度表达，不接受简单的"我也是"。
27. 双边 title 根据状态决定 wording：共鸣 / 差异。
28. **核心：枝桠接力式生长。** 回应有新信息时长子枝桠。只有单边和双边两种状态。
29. 记忆碎片可复用到其他树。

### 两种树的规则异同

30. Profile 树是"自画像碎片"（关于我），PVP 树是"关系碎片"（关于我们）。
31. Profile 树不枯萎、无终点、无双边、description 完全可见。
32. 三种 title 风格需要不同的生成 prompt。
33. 暂定 slogan："你说的每一句话，都在某个地方生根。"

### 树的成熟度与生命周期

34. PVP 树有成熟度进度（广度 × 深度 × 双边比例）。数值待定。
35. 树间视觉差异应直观可见。
36. 允许自然淘汰。

### 回访推送

37. 四种触发：成就、关系进步、森林变化、关系降级。
38. 频控先粗放。
39. 推送要让用户想起具体的变化，不是抽象通知。

### 见面出口

40. 见面是树的自然终点。成熟后提示"好时机"，不强制。
41. 花苞机制：保留未完全展开的枝桠方向作为话题储备。

### 对话策略与 Prompt 架构

42. 没有独立兜底机制。兜底 = P1 的对话能力。
43. 对话结构："散开 → 收拢 → 深入"。
44. 核心策略：抽象再探索、follow-up 优先、evoking over diagnosing。
45. 四条禁区：不贴标签、不诊断、不问人口统计、不碰脆弱性。
46. P1 和 P2 独立分开调用。
47. 枝桠实时生成：对话过程中用户就能看到树的生长。
48. Maximize 用户输出，不降低标准。

## 11. 研究文献索引

> 支撑 Claw 对话设计和 profile elicitation 策略。

### 对话引导深度自我表达

**Lee et al. "I Hear You, I Feel You"** — CHI 2020
Chatbot 先做自我披露能持续促进用户更深层表达。Reciprocity 不需要对等的生活经验。

**Croes & Antheunis, Longitudinal Study** — Interacting with Computers 2023
用户初始互动时自我披露最高，之后逐渐下降。**第一次对话是黄金窗口。**

**Luo et al. Self-disclosure to Conversational AI** — Personal and Ubiquitous Computing 2024
非人格化 AI 反而比拟人化 AI 获得更多自我披露。支持"非人但有温度"定位。

### AI Profile Elicitation

**ProfiLLM** — arXiv 2025 · 通过自然对话隐式推断用户画像。

**IMPChat** — arXiv 2021 · 从对话历史学习隐式用户画像，语言风格和偏好分开建模。

**PaRT** — arXiv 2025 · 主动提问 + 记忆提取双通道实时构建画像。

### Preference Elicitation

**Gadiraju et al. "Should We Tailor the Talk?"** — UMAP 2025 · 允许用户切换对话风格的 flexible 模式效果最好。

**Priyogi, Preference Elicitation Strategy** — WSDM 2019 · 每个问题应最大化信息增益。

**Gao et al. CRS Survey** — AI Open 2021 · 用户耐心有限，需在信息收集和价值交付之间控制节奏。

### Self-Disclosure 心理学

**Ho, Hancock & Miner** — Journal of Communication 2018 · 用户感知 AI 不会评判，比面对真人时披露更多。

**Kim et al. Reciprocal Self-Disclosures** — Archives of Design Research 2024 · Chatbot 主动自我披露时，用户产生更强信任感。

**Li et al. Sensitive Health Conversations** — IJHCI 2025 · 感知匿名性 + 感知有用性共同驱动深度披露。

### Motivational Interviewing

**CAMI (STAR framework)** — ACL 2025 · 先推断用户心理状态再决定对话策略，优于直接提问。

**Bickmore et al. MI Agent** — AAAI 2011 · OARS 框架可编码到对话 agent。Reflection 同时实现"被理解感"和"更深表达"。

**Haug et al. MIcha** — IJHCS 2025 · MI 几轮对话内就能生效。

**Miller & Rollnick, Motivational Interviewing** — 经典框架。核心区分：**evoking vs diagnosing**。Labeling 是杀死开放性的主要方式。

### 友谊形成与关系递进

**Aron et al. "The Experimental Generation of Interpersonal Closeness"** — PSPB 1997
原始 36 Questions / **Fast Friends Procedure**。三层递进：假设性/偏好 → 个人价值观和经历 → 脆弱性和情感暴露。原本为友谊设计，跨文化/远程/线上有效。第一次 setup 只覆盖前两层。[原文 PDF](https://www.stafforini.com/docs/Aron%20et%20al%20-%20The%20experimental%20generation%20of%20interpersonal%20closeness.pdf)

**Altman & Taylor, Social Penetration Theory** — 1973
自我披露的广度和深度。早期先扩广度，再选择性深入。四阶段：Orientation → Exploratory Affective → Affective → Stable。[设计启示：先铺广度再深入]

**Huang et al. "It Doesn't Hurt to Ask"** — JPSP 2017
2000+ 段对话分析。**Follow-up questions 是最强的好奇心信号**，显著优于 topic switching。[原文 PDF](https://www.hbs.edu/ris/Publication%20Files/Huang%20et%20al%202017_6945bc5e-3b3e-4c0a-addd-254c9e603c60.pdf)

**Kardas, Kumar & Epley, "Overly Shallow?"** — JPSP 2022
人们系统性高估深度对话的尴尬程度。对方比预期更感兴趣。[原文 PDF](https://www.apa.org/pubs/journals/releases/psp-pspa0000281.pdf)

**Sprecher, Treger & Wondra, "Taking Turns"** — JESP 2013
即时轮流 reciprocity 产生更高亲密感。长时间独白反而降低好感。

**Sprecher (2021)** — JSPR · FFP 在亲密度和好感上显著优于 small-talk 和 unstructured disclosure。线上有效。

### 高质量倾听与感知回应性

**Reis & Shaver, "Intimacy as an Interpersonal Process"** — 1988
亲密感取决于对方怎么回应。Perceived Partner Responsiveness 三维度：Understanding、Validation、Care。

**Itzchakov & Reis (2023)** — Current Opinion in Psychology · 高质量倾听让人更少焦虑、更少防御。效果量 d=1.19。

**Itzchakov & Weinstein (2022)** — SPPC · 高质量倾听甚至降低偏见态度。核心：感到对方真的在理解自己时会更开放。

### 友谊形成的实践框架

**Lydia Denworth, "36 Questions for Friendship"** — 2020 · Aron 36Q 的友谊适配。[PDF](https://lydiadenworth.com/wp-content/uploads/2020/02/36-Questions-Friendship-Denworth.pdf)

**"We're Not Really Strangers" (WNRS)** — 卡牌游戏。三层：Perception → Connection → Reflection（对话的 meta-reflection，Aron 没有的独特设计）。Rocheville & Buccheri (2025, Sage) 验证效果。

**Berkeley Greater Good, "36 Questions for Increasing Closeness"** — [在线实践指南](https://ggia.berkeley.edu/practice/36_questions_for_increasing_closeness)
